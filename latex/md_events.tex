\item The {\ttfamily prevent\+Default()} method of the Event interface tells the user agent that if the event does not get explicitly handled, its default action should not be taken as it normally would be.

 \hypertarget{md_events_autotoc_md11}{}\doxysubsection{\texorpdfstring{Concept for shadow DOM}{Concept for shadow DOM}}\label{md_events_autotoc_md11}
So, this was actually so confusing for me and that\textquotesingle{}s why I am explaining this all. So when any event handler is attached and whenever event is provoked using user interaction or {\ttfamily dispatch\+Event()}, this all happens.~\newline
~\newline
 First {\ttfamily path} is created starting from the element that had the event started and going to the top of the DOM. Then the {\ttfamily composed\+Path()} method does further processing when called. There can be different cases here !~\newline
 1) The element is outside a shadow tree, then it just goes from that element to the top which could be Document or window. 2) The element is inside a shadow tree. It also has 4 cases\+:-\/ 1) Shadow tree is closed and {\ttfamily composed} in event is true, then the path includes the shadow root to the top. The hierarchy inside the shadow tree isn\textquotesingle{}t included. 2) Shadow tree is closed and {\ttfamily composed} in event is false, path just contains the shadow root. 3) Shadow tree is open and {\ttfamily composed} in event is true, then the path has the full order from the element invoked to the top including shadow tree hierarchy. 4) Shadow tree is open and {\ttfamily composed} in event is false, then the path has elements from the element invoked till the shadow root.

It also removes the shadow roots !

This is how the {\ttfamily path} for the current event is calculated. Furthermore, the {\ttfamily compose\+Path()} method works on this path to have the shadow roots removed and also not including the shadow DOM notes if its mode is closed.
