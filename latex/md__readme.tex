An HTML Visualizer \& DOM Library\hypertarget{md__readme_autotoc_md1}{}\doxysection{\texorpdfstring{DOM}{DOM}}\label{md__readme_autotoc_md1}
A {\ttfamily \doxylink{class_document}{Document} Object Model} for storing and working of tree for HTML and XML documents.

Alongside, it consists of an {\ttfamily HTML Visualizer} to visualize how your html looks to the browser.

It defines a complex tree of classes with preorder depth first traversal order.\hypertarget{md__readme_autotoc_md2}{}\doxysubsection{\texorpdfstring{What exactly is it ??}{What exactly is it ??}}\label{md__readme_autotoc_md2}
Basically, it is a very complex tree implementation strictly abiding to the rules of the \href{https://dom.spec.whatwg.org/}{\texttt{DOM STANDARD}} defined by an organization named \href{https://whatwg.org/}{\texttt{What\+WG}}.

It is the most crucial part of a browser \& they basically depend on this. The functions you use {\ttfamily add\+Event\+Listener()}, {\ttfamily dipatch\+Event()}, {\ttfamily document.\+write()}, etc.. are all written in this library \+:)

It is the {\ttfamily intermediate} which is created when {\ttfamily HTML} is parsed.

So let\textquotesingle{}s understand this clearly ! In broader sense\+:-\/

When we load a website, its HTML, CSS and JS is fetched and every component is parsed. ~\newline

\begin{DoxyItemize}
\item First {\ttfamily HTML} is parsed and {\ttfamily DOM} ( \doxylink{class_document}{Document} Object Model ) tree is created !
\item Then {\ttfamily CSS} is parsed and {\ttfamily CSSOM} ( CSS Object Model ) is created !
\item Both the {\ttfamily DOM} and {\ttfamily CSSOM} are combined to create the {\ttfamily Render Tree} !
\item Finally using the {\ttfamily Render Tree}, we see the website on the screen after~\newline
 some processes of layout, painting , compositing, etc..
\end{DoxyItemize}

\begin{quote}
This repository implements the {\ttfamily DOM tree} for the HTML parsing ! \end{quote}
